# Учёт рабочего времени

Небольшое веб-приложение для учёта рабочего времени сотрудников. Все имена и задачи в примерах вымышлены.

![Экран приложения](docs/screenshot.png)

Что умеет приложение:

- добавляет сотрудников
- запускает и останавливает таймер с описанием задачи
- показывает записи и общее время каждого сотрудника за выбранный период
- хранит данные в файле SQLite, поэтому данные остаются после перезапуска

Стек: Node.js 22, Express 5, встроенный модуль `node:sqlite`, интерфейс на HTML, CSS и JS без сборки.

## Запуск

Нужен Node.js 22.13 или новее.

```bash
npm ci --no-audit --no-fund
npm start          # http://localhost:3000
npm run seed       # вымышленные сотрудники и записи (только в пустую базу)
```

## Проверки

```bash
npm test                          # 32 теста API
npx playwright install chromium   # один раз, браузер для тестов интерфейса
npm run test:ui                   # 12 тестов интерфейса в браузере
```

Тесты покрывают основные сценарии, в том числе:

- **повторный запуск таймера** — API отвечает 409, страница показывает ошибку и кнопку «Стоп»
- **пустой отчёт** — API отвечает 200 с пустым списком, страница показывает подсказку
- сохранение данных после перезапуска
- старт и стоп таймера, итоги за период, границы периода

Полный список: [docs/testing.md](docs/testing.md).

### Примеры запросов

1. Постановка задачи — текст тестового задания целиком, без изменений.
2. Ответы на уточняющие вопросы Claude Code:

   > Стек: Node + Express + SQLite. Таймер: один на сотрудника, повторный запуск возвращает ошибку 409.

3. Ревью, которое Claude Code передал субагенту (сокращено):

   > Review a small time-tracking web app for correctness bugs. Read-only: do NOT edit files. Look for: real bugs in logic, SQL, time/period math, time zones (DST), validation gaps, error handling, UI state bugs, XSS, test gaps for main scenarios. Report at most 8 findings, most severe first. For each: file:line, the concrete input/state that triggers it, the wrong result, and a suggested fix.

4. Проверка в браузере: «таймер уже запущен в другой вкладке» — запустить таймер через API, затем нажать «Старт» на странице, где ещё видна кнопка «Старт».

## Найденные и исправленные ошибки

Всего нашлось 29 ошибок: их нашли тесты, проверка в браузере, два код-ревью и проверка UI/UX. Самые важные:

- **Дубль имени на кириллице проходил проверку.** `COLLATE NOCASE` в SQLite не различает регистр только у латиницы, поэтому «Борис» и «борис» считались разными. Исправление: колонка `name_key` с `toLocaleLowerCase('ru')` и уникальным индексом.
- **После старта таймера страница показывала ошибку.** Функция `el()` передавала `dataset` в `Object.assign`, а это свойство можно только читать. Сервер таймер запускал, а страница оставалась со старой кнопкой.
- **Сервер принимал любой текст как дату.** `Date.parse('1')` даёт дату в 2001 году. Исправление: строгая проверка ISO-формата с часовым поясом.
- **Итог отчёта уменьшался, если часы сервера уходили назад.** Исправление: доля каждой записи не меньше нуля, и конец записи не раньше начала.
- **Изменения из другой вкладки не появлялись.** После ответа 409 на странице оставалась кнопка «Старт», и таймер нельзя было остановить. Исправление: после ошибки страница загружает актуальное состояние и опрашивает сервер раз в 30 секунд.
- **На телефоне страница прокручивалась вбок**, а у полей не было видимых подписей. Исправление: таблица прокручивается внутри своего блока, у полей есть подписи.

Часть ошибок допустил сам Claude Code. Каждую находку ревью я проверил перед исправлением. Полный список с причинами и исправлениями: [docs/bugs-and-reviews.md](docs/bugs-and-reviews.md).
